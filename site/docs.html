Stellagate Core Documentation

Pre-flight destination validation engine for the Stellar network. Verify memo mandates, trustlines, SAC compatibility, and malicious account blocks before signing transactions.

Quick Start

Stellagate runs client-side in the browser, in Node.js, Cloudflare Workers, and Deno. It has zero external dependencies other than standard fetch and crypto primitives.

Terminal 
npm install @stellagate/core

Verify an Address in 3 Lines

TypeScript 
import { check } from "@stellagate/core";

const verdict = await check({
  to: "GABFQIK63R2NETJM7T673EAMZN4RJLLGP3OFUEJU5SZVTGWUKULZJNL6",
  network: "public"
});

if (verdict.status === "block") {
  console.error("Payment rejected:", verdict.reasons[0].message);
}

Decision Architecture

Every pre-flight check produces a deterministic Verdict object containing a single triage status and an array of granular Reason items.

Status Visual Badge Definition & Wallet Behavior
ok GO Payment destination is fully verified. Safe to sign and broadcast.
warn WARN Destination is valid but unconfirmed or unmemoed on a generic exchange. User review strongly advised.
block BLOCK Funds will be lost or permanently rejected by network consensus. Wallets must disable the Submit button.

Supported Address Types

Stellagate automatically parses and normalizes every modern Stellar address standard without requiring manual type hints:

  • Classic Ed25519 (G...): 56-character standard Stellar public keys.
  • Muxed Accounts (M...): SEP-23 69-character multiplexed addresses bundling a classic G address and an embedded 64-bit integer ID.
  • Soroban Contracts (C...): 56-character smart contracts and passkey smart wallet addresses.
  • SEP-2 Federation (user*domain.com): Resolved transparently over HTTPS federation endpoints into target accounts and memos.
  • Secret Key Refusal (S...): Immediately catches pasted secret keys, blocking submission and warning the user of private key exposure.

Dual-Source Memo Verification

Only 13% of exchange omnibus accounts set the on-chain SEP-29 memo_required flag. Stellagate bridges this gap by cross-referencing both on-chain flags and the public StellarExpert directory of known exchange hot wallets.

TypeScript 
const verdict = await check({
  to: "GCLWB6BMNLOKYZT6AH7O2RMMQ225PVIUK72W7X4W654N3VP63625NL6M", // Kraken
  memo: undefined, // omitted
});

// verdict.status === "block"
// verdict.reasons[0].code === "memo_required"
// verdict.entry.name === "Kraken Deposits"

Passkeys & Smart Wallet Compatibility

Soroban smart contract accounts (C-addresses) invoke contract functions instead of emitting classic payment operations. Because Soroban operations do not carry memo fields, transfers from contract accounts directly to exchange omnibus addresses result in irreversible loss of funds.

When from: "C..." is provided, Stellagate flags this incompatibility before the transaction is authored and suggests routing through an intermediate classic account.

Asset Holdability & SAC Verification

Sending a non-native asset (e.g. USDC, EURC, AQUA) requires verifying that the recipient has established a valid trustline with sufficient headroom:

TypeScript 
const verdict = await check({
  to: "GA5ZSEJYB37JRC5AVCIA5MOP4RHTM335X2KGX3IHOJAPP5RE34K4KZVN",
  asset: "USDC:GA5ZSEJYB37JRC5AVCIA5MOP4RHTM335X2KGX3IHOJAPP5RE34K4KZVN",
  amount: "5000",
  network: "public"
});

API Reference: check()

The primary entrypoint. Evaluates all safety checks concurrently with bounded timeouts and offline fallbacks.

Signature

function check(input: CheckInput, options?: CheckOptions): Promise<Verdict>;

CheckInput Interface

interface CheckInput {
  /** Target address: G, M, C, or user*domain.com */
  to: string;
  /** Optional sender address: G or C account */
  from?: string;
  /** Optional memo entered by the user */
  memo?: string;
  /** 'native' (XLM) or CODE:ISSUER format */
  asset?: string;
  /** Amount string for trustline balance headroom checks */
  amount?: string;
  /** Target network: 'public' or 'testnet' (default: 'public') */
  network?: "public" | "testnet";
}

Verdict Interface

interface Verdict {
  /** Overall triage disposition */
  status: "ok" | "warn" | "block";
  /** Human-readable explanation */
  summary: string;
  /** Granular breakdown of individual check results */
  reasons: Reason[];
  /** Resolved destination metadata */
  destination: Destination;
  /** Directory record if known exchange or entity */
  entry?: DirectoryEntry;
  /** Whether a memo is mandatory */
  memoRequired: boolean;
}

Pluggable Sources & Private Infrastructure

By default, Stellagate uses public Horizon and RPC nodes. In high-volume production deployments, inject your private authenticated RPC endpoints or custom caching layers:

TypeScript 
import { check, horizonAccountSource, rpcContractSource } from "@stellagate/core";

const verdict = await check(input, {
  accounts: horizonAccountSource("https://stellar-horizon.my-enterprise.com"),
  contracts: rpcContractSource("https://stellar-rpc.my-enterprise.com")
});
